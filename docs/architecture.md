# 拾光小铺系统设计

## 技术与运行方式

后端使用 Spring Boot 3.5.16，Java 编译基线17，本机以 Microsoft OpenJDK 21 运行。前端使用 Vue 3.5 和 Vite 7。数据库为 MySQL 8.4，Flyway 按版本执行建表及样例数据迁移。Vue 构建结果打包进后端，正式运行时通过同一个地址访问页面与接口。

本地服务仅监听回环地址。工具、数据库、随机生成的本地密码及日志保存在被 Git 忽略的 `.local/` 下。

## 数据模型

- `product`：商品、分类、价格、可售库存、上下架状态和资料来源。
- V11增加多图、规格JSON及来源价格、货币、采集时间；来源价格与本站演示价分别展示。
- `app_user`：顾客及管理员；密码保存为 BCrypt 哈希。
- `cart_item`：按顾客与商品保存购物袋数量。
- `shop_order`：订单、收件资料、状态、总金额与请求幂等键。
- `order_item`：商品名称、图片、单价与数量快照，商品后续修改不改变历史订单。
- `payment_record`：演示付款凭证，每个订单只允许一条。
- `mail_outbox`：与发货状态一起提交的邮件任务，记录发送次数与结果。

## 关键业务

下单先锁定当前顾客，读取购物袋，并通过条件更新扣减库存。所有商品扣减、订单建立、订单项写入及清空购物袋放在同一事务中；任一商品库存不足就全部回滚。客户端提交的金额不会作为订单金额使用。

同一顾客的同一个 `Idempotency-Key` 返回已有订单。演示付款、取消订单和确认收货的重复请求不会重复记账或恢复库存。订单状态依次为待付款、待发货、已发货、已完成；待付款订单可取消并恢复库存。

管理员删除商品采用下架方式，保留历史订单关联。销售额仅计算已付款、已发货和已完成订单；销售趋势按付款日期统计。

销售报表支持日期范围及排除预置数据。订单数量按创建日期过滤，收入及畅销榜按付款日期过滤，避免跨日期付款漏算；CSV使用UTF-8。上传图片保存在独立持久化目录，商品记录保存生成的安全路径。

前端保存筛选、排序、页码及返回浏览位置，翻页后滚动到商品区。购物袋有文字导航和常驻结算入口；登录失效统一要求重新认证，未完成的收件资料仅在当前页面内存中暂存，不持久保存，也不自动重放下单请求。

## 登录与权限

Spring Security 通过服务端 Session 保存登录状态，登录时更换 Session ID。接口按登录状态和管理员角色授权；顾客读取订单时额外检查订单归属。写操作必须携带服务端签发的 CSRF 令牌。前端不会在本地存储中保存登录凭证。

## 邮件与付款的边界

付款是明确标识的课程演示，不产生实际扣款。当前邮件通过 SMTP 到达本地测试邮箱，并保存真实 `.eml` 文件，状态显示 `CAPTURED`；这不等于外部邮箱已收件。可通过环境变量接入正式 SMTP，正式提交报告前仍需验证老师要求的真实收件流程及付款验收口径。
